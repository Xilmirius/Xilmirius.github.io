¿Por qué PostgreSQL y no Mongo?

Para este proyecto concreto, me quedaría con PostgreSQL simplemente porque Supabase ya te lo da.

No ganás nada metiendo Mongo:

Supabase ─── PostgreSQL
     │
     └── Realtime

es mucho más sencillo que:

Supabase ─── Realtime
     │
     └── MongoDB Atlas

Tendrías dos proveedores cuando Postgres ya es suficiente.

Y para datos de partidas tampoco necesitás las ventajas particulares de MongoDB.

Incluso algo tan sencillo como:

games
players
matches

te alcanza perfectamente.

Y hay una decisión todavía más importante

Yo no guardaría el estado del juego en Supabase.

No hagas:

Player mueve
     ↓
Supabase
     ↓
Otro Player

Ni:

60 updates/segundo
       ↓
   PostgreSQL

El flujo debería ser:

               SUPABASE
                  │
            crear partida
            encontrar partida
               signaling
                  │
                  ▼
             WEBRTC P2P
                  │
        ┌─────────┴─────────┐
        │                   │
       HOST                CLIENT
        │                   │
    game state          input/state
        │                   │
        └───────────────────┘

El host es el servidor del juego, conceptualmente, aunque en realidad sea el navegador de un jugador.
